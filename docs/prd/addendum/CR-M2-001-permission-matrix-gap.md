## 1 为什么要有这份补遗

B2 阶段 RBAC 落地时，把 PRD §2.2 的「功能模块视图」翻译成**可执行的权限点**时，发现 9 行功能模块对应不上实现：档案读写、评估任务列表、敏感字段明文、国标规则回溯、评估单作废共 **6 个权限点**在主文档 §2.2 中**无对应行**，数据可见范围（`data_scope`）与异常行为处置也**无口径**。

CR-M2-001 已经 CCB **会签并落地**（代码、种子、契约、文档四处已对齐），但主文档尚未回写，存在「文档口径 < 实现口径」的偏差。为避免**直接覆盖主文档**在未追认期间造成口径混乱，采「**主文档加横幅 + 独立补遗 → 追认后再覆盖**」三步走。

**追认前**：主文档 §2.2 仍为现行产品口径；研发实现以本补遗 + 《B2 权限点清单》为准。
**追认后**：本补遗内容并入主文档 §2.2，横幅撤除，本件归档。

### 2.1 数据域 `data_scope`（补）

权限点回答「**能不能做**」，数据域回答「**能看到谁的数据**」。二者分离，避免为「本人 / 绑定对象 / 本机构 / 全量」各分裂一套权限点。

| 角色 | `data_scope` | 可见范围 |
|---|:--:|---|
| 老人 ELDER | 1 本人 | 仅本人档案与评估数据 |
| 评估员 ASSESSOR | 1 本人 | 仅本人承接的评估任务及其对象 |
| 家属 FAMILY | 2 绑定对象 | 已绑定老人的已发布数据 |
| 机构管理员 ORG_ADMIN | 2 本机构 | 本机构下全部老人与人员 |
| 监管 SUPERVISOR | 4 全量 | 全量（写入动作默认拒绝） |

> 数据域由第四闸 `DataPermissionInterceptor` 在 SQL 层自动追加过滤，**不依赖业务代码自觉**；`data_scope = 4` 的写入动作默认拒绝。

### 2.2 行为异常检测（补）

`elder:archive:read` 五角色全授予，横向越权的兜底**不靠权限点拆分，靠行为检测**：

| 项 | 口径 | 配置项 |
|---|---|---|
| 触发条件 | 同一账号对档案类接口（`elder:archive:read`）**滑动 1 小时**内调用 **> N**，默认 **N=50** | `threshold` / `window-minutes` |
| 处置 | 写审计事件 `ARCHIVE_ACCESS_ALERT` + 通知监管角色；同一窗口内对该账号**只告警一次** | `mode` |
| 强度档位 | `off` 旁路 / `audit` 只留痕 / **`alert` 留痕+通知（默认）** / `enforce` 留痕+通知+拒绝 | `mode`，未知值回落 `alert` |
| 监控范围 | 默认 `ELDER,FAMILY,SUPERVISOR`（非护理角色） | `monitored-roles` |
| 失败策略 | 计数设施异常时**失败开放**（监控抖动不得放大为业务拒绝） | — |

> ⚠ **`enforce` 本期默认不启用**：`elder:archive:read` 是非敏感权限点，拒绝请求会让无 `X-Second-Verify-Token` 的客户端直接失败，属契约破坏性变更，超出本 CR 授权范围。启用前须完成契约变更。响应时限与处置流程见《B2-archive-access-alert-sop.md》。

### 2.3 敏感权限点（补）

4 个，均需**二次验证 + 全留痕**，其中 2 个**不常驻授权**（运行时临时提权）：

`data:export`（导出）· `evaluation:order:void`（作废评估单）· `account:family:unbind`（解绑）· `data:reveal`（敏感字段明文）

## 3 与主文档现行 §2.2 的差异

| 差异 | 现行 §2.2 | 本补遗 |
|---|---|---|
| 权限码 | 无 | 每行补 `perm_code` 列（22 个权限点全部落到功能模块） |
| 功能行 | 9 行 | **15 行**（+ 老人建档 / 查看老人档案 / 评估任务列表 / 敏感字段明文 / 国标规则回溯 / 评估单作废） |
| 数据可见范围 | 未定义 | 新增 §2.1 `data_scope` 五角色口径 |
| 异常行为处置 | 未定义 | 新增 §2.2 滑动窗口告警口径（N=50 / 1h / 四档 `mode`） |
| 敏感点 | 仅「导出/批量操作」标注需二次验证 | 明确 4 个敏感点，其中 2 个不常驻授权 |

**未改动**：主文档 §2.2 原有 9 行的授权结论（✅/❌/🔶/👁）**全部保持不变**，本次只做「补列 + 补行 + 补口径」，不推翻任何既有产品决策。
