## 2. 方案文档要点（`15_短信验证码通道技术方案.md`）

**接口清单（4 个）**：`SMS-01` 图形验证码 → `SMS-02` 发送短信验证码 → `SMS-03` 校验 → `SMS-04` ticket 兑换登录态。

**防刷**：频控矩阵 + 图形验证码前置 + 错误锁定 + 黑名单 + 重放检测。
**存储/核销**：验证码生成规则 + 存储 + **一次性核销**。
**服务商**：主备选型 + **备案要求** + 通道设计 + 监控告警。
**四端适配**：微信 / **抖音（D-1 重点）** / iOS / 安卓 + 统一鉴权。
**安全合规**：PIPL / 隐私政策 / 平台合规；责任分工；验收标准（功能 + 防刷）。

## 3. 与本项目既有红线/机制的接口

| 事项 | 结论 |
|---|---|
| **ADR-0003**（雪花 id / 0 外键 / `DATETIME` / 显式给 id） | 新表必须照办（无 `AUTO_INCREMENT`、0 物理外键、手写 SQL 显式给 id） |
| **ADR-0004**（唯一 `@Scheduled`） | 验证码**过期清理**若要做定时，**不得新增 `@Scheduled`** —— 要么走 Redis TTL（推荐），要么并入既有链路（会推高动作数）。**推荐 Redis TTL，零调度** |
| **数据域第三闸** | 新表的读路径必须登记或显式论证为"无归属语义"（**不留暗区**）；若为登录前置端点（未登录态），需在契约 `x-data-scope` 里显式声明 `public` |
| **鉴权四闸** | `SMS-01/02/03` 属**未登录前置**端点 ⇒ 必须进 `SecurityConfig` 白名单 + `ControllerAuthorizationCoverageTest` 的 `CONTROLLERS` 双处登记 + 契约 `x-required-permission` 口径（前置端点如何表达"无权限要求"须**显式**，不能留空） |
| **敏感字段** | 手机号一律 `SensitiveFieldCodec`（`phone_enc` + `phone_hash`），**禁明文落库**；日志/审计**不得**打印手机号与验证码 |
| **二次验证口径**（`CR-M2-002` §8.7） | 验证码**一次性消费 + 失败不退**（与二次验证凭据同口径，防重放优先） |
| **错误语义** | 业务失败一律 **HTTP 200 + `R.code`**；未认证才 401+`10002`；限流 `10429`；冲突 `10005`；不存在/越界 `10004`（同码不泄露存在性）★ **登录前置端点尤其要防"手机号存在性枚举"** |
| **门禁三件套** | 新增端点 ⇒ 契约 `implemented +4`、`verify-openapi.sh` 断言上升、`ControllerAuthorizationCoverageTest` 白名单可能需扩；新增表 ⇒ `verify-schema.sh` 断言上升；`mvn verify` 只升不降 |

## 4. 红线（承接卡面 + 本次核查补强）

1. 验证码**一次性消费 + 失败不退**（承 `CR-M2-002` §8.7）。
2. 手机号**不得明文落库**，不得进日志/审计（承 `SensitiveFieldCodec` 红线）。
3. 下发接口**必须限流**（防短信轰炸与费用攻击）—— 频控矩阵须**可断言**（DB 级门禁，承 D5-R1 教训）。
4. ★ **防手机号存在性枚举**（本次补强）：`SMS-02` 无论手机号是否已注册，**返回必须一致**（不得因"未注册"返回不同码/不同文案），否则成探测接口 ⇒ 与 `10004` 同码不泄露存在性同一哲学。
5. ★ **通道不可用时的行为必须显式**（本次补强）：生产未配置服务商时应 **fail-closed 且可观测**（参考 `SensitiveFieldCodec` 的条件装配 → `40001` 口径），**不得"静默假装发成功"**（卡面原话："不造轮子也不假装存在"）。
6. 合规前置**未定稿前不得在生产开启自助核身**（核身强度分级须 DPO 签署）。

## 7. 验收判据（拟，交 QA 独立复核）

1. `SMS-02` 下发：验证码**不落明文**（Redis/表中为 hash 或加密）、**进日志为掩码**。
2. **一次性消费**：同一验证码二次校验必失败；**失败不退**（输错一次即失效，须重新申请）。
3. **频控可断言**：同手机号 N 秒/N 次上限、同 IP 上限、图形验证码前置；超限返回 **`10429`**。
4. ★ **防枚举**：未注册手机号与已注册手机号，`SMS-02` 返回**完全一致**（响应体 + `R.code` + 时延量级不构成区分）。
5. ★ **fail-closed**：通道未配置/不可用时**显式失败**（不静默成功），且错误可观测。
6. `SMS-03/04`：校验通过后签发 ticket，ticket **一次性**且短 TTL，兑换登录态走既有双令牌。
7. 四门禁只升不降；DB 级门禁覆盖新增手写 SQL（承 D5-R1：mock 单测对手写 SQL 零区分力）。
8. 合规：`consent_record` 留痕 + 隐私政策版本可追溯（若 E1 含合规段）。
