## 1 变更背景：为什么必须单独立案

PRD 权威位在 2026-10-11 首次入仓时由 **v1.1 切换到 v1.2**，同时登记了缺口 **G1**：

> **v1.2 未挂 CCB 追认横幅**。2026-10-10 的限期顺延订正（限期 → **2026-10-17**）当时只写进了 v1.1 文件，v1.2 文件里**没有**。

关键性质（见 README §3 G2，本次再确认）：

- §1.3 修订记录**累积自 v1.1**，国标对齐口径（CR-M1-001）因此**已继承**；
- 但**横幅不属于修订记录**，因此**不随升版继承**。

⇒ 权威位切换后若不在 v1.2 补挂，会出现「**换了个文件，提醒就没了**」——10-17 之后无人被提醒，CCB 追认事项静默漂流。这正是 G1 必须单独处置、不可假设"升版自动带上"的原因。

**PM 裁决（2026-10-11，G1）**：选择 **① 移植横幅至 v1.2**（而非②维持不改、仅由 README 常驻提示）。

## 3 为何不递增版本号（重要）

| 判据 | 说明 |
|---|---|
| **口径未变** | 本次改动只在文首追加治理提示，**正文（含 §2.2 权限矩阵、§1.2 范围、§3 功能点、§1.4 国标口径）一字未改**。版本号是口径的版本，不是文件的版本。 |
| **先例一致** | v1.1 在 2026-10-10 的「限期顺延」订正中明确约定「**不升版，文档仍为 v1.1**」。本次沿用同一规则。 |
| **PM 裁决原文** | 裁决措辞为「**移植横幅至 v1.2**」，即移植到*现有的 v1.2*，而非产出新版。 |
| **改名代价** | 若升 v1.3，须同步改文件名、`docs/prd/README.md` 版本索引、口径链路 §2.1、以及所有引用该文件名的地方 —— 为一处治理提示引入全链路同步风险，收益为负。 |

> 版本号的递增**留给真正的口径变更**：CR-M2-001 的 CCB 追认一旦通过，§2.2 并入正文，届时**才应**升版并同步归档补遗件。
