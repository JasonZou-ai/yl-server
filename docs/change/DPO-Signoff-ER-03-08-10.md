## 一、ER-03 保留期口径 —— 请确认

### 1.1 已落库的口径（分档）

| 数据类别 | 保留期 | 落库位置 | 依据 |
|---|---|---|---|
| 评估记录 | **5 年** | `eval_order.retain_until` | 纪要 §三 ER-03 裁决 |
| 评估报告 | **5 年** | `eval_report.retain_until` | 同上 |
| 监管报表 | **5 年** | `supervise_report.retain_until` | 同上 |

**实现方式**：仅新增 `retain_until DATETIME NULL` 列 + `idx_retain` 索引（4 张表），

该列是「过期清理」与「归档（超保留期 → 仅监管可见）」两个机制的**统一触发依据**（PRD §4.4）。

## 二、ER-08 告知同意留痕 —— 请确认

### 2.1 已落库的表结构

**新表 `consent_record`**（`02_schema.sql` 第 643 行起）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `subject_type` / `subject_id` | VARCHAR(16) / BIGINT | 主体类型 `ELDER`/`FAMILY`/`STAFF` + 主体 ID |
| `policy_code` / `policy_version` | VARCHAR(32) / VARCHAR(16) | 隐私政策编号 + 版本号 |
| `consent_at` | DATETIME | 同意时间 |
| `consent_channel` | VARCHAR(16) | 渠道 `APP`/`WECHAT`/`DOUYIN`/`IOS`/`PAPER` |
| `scope_json` | JSON | **授权收集范围快照**（同意时的范围原文，防止政策改版后无法举证） |
| `revoked_at` | DATETIME NULL | **撤回时间** |
| `ip` | VARCHAR(45) | 留痕 IP |
| 索引 | — | `idx_subject`（主体）/ `idx_policy`（政策版本）/ `idx_consent_time`（时间） |

**设计要点**：业务授权表（`elder_authorization`）与隐私政策同意**是两件事**，故独立建表
——业务授权解决「能否看数据」，`consent_record` 解决「个保法知情同意的举证」。

### 2.2 覆盖场景

| 场景 | 对应任务 | 说明 |
|---|---|---|
| 首次使用 / 隐私政策弹窗前置 | B3 各端工程（`rt97qP` / `rjYy5o` / `r91fla` / `r51i4V`） | 同意后写入 `consent_record` |
| 人脸核身（家属绑定） | D3 家属协作（`rYs0s3`） | 属**敏感个人信息**，须**单独同意** |
| 敏感操作二次验证与留痕 | B2（`ri91pT`） | 查看明文敏感字段需二次验证 + 留痕 |

### 2.3 请 DPO 确认的三点

| # | 确认项 | 我方口径 | 请确认 |

| 1 | **字段是否满足举证要求** | 主体 + 政策版本 + 时间 + 渠道 + **范围快照** + 撤回时间 | ☐ 满足 ☐ 需补充字段（请注明） |
| 2 | **撤回后的数据处理** | 拟：`revoked_at` 置位后**停止新收集**，已收集数据按 §一 保留期与业务必要性处理 | ☐ 同意 ☐ 需调整 |
